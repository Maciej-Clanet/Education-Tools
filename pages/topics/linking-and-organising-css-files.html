Linking and organising CSS files

HTML describes a page's content and structure. A separate CSS file controls how that content looks. Learn how the HTML file finds its CSS and how to keep stylesheets organised across a website.

Document Recap

The CSS connection belongs in the HTML head

The <body> contains the page content people normally see. The <head> contains information and resources the page needs—including its connection to CSS.

<head>Information and resources the page needs
<body>Headings, paragraphs, images, forms, and other visible content 
<!doctype html>
<html>
  <head>
    <!-- The CSS connection will go here -->
  </head>
  <body>
    <h1>Our website</h1>
  </body>
</html>
website/
  • HTML index.html
  • folder css/
    • CSS common.css

CSS lives in a separate .css file

index.html describes the content and structure. common.css contains styling for the page.

The filenames are examples, not special required names. The important clue is the .css extension.

Make the Connection

Link the stylesheet from inside head

One void element connects the HTML document to the CSS file:

<link rel="stylesheet" href="css/common.css">
<link>Connect a resource

This is a void element, so there is no closing link tag.

rel="stylesheet"Explain the relationship

This tells the browser the resource is a stylesheet for this page.

href="css/common.css"Give its location

This tells the browser where to find the CSS file.

Two files, two different jobs

Why css/common.css is wrong here:

Starting from pages/sales.html, it sends the browser towards pages/css/common.css. That folder does not exist in this project.

More Than One File

One HTML page can link multiple stylesheets

Link multiple CSS files when the split makes the project easier to organise.

<head>
  <link rel="stylesheet" href="css/common.css">
  <link rel="stylesheet" href="css/home.css">
</head>
common.css

Shared header, navigation, footer, buttons, and other site-wide styling.

home.css

Styling only needed by the home page.

Useful split, not a fixed rule:Filenames such as common.css and home.css describe one sensible approach. Choose names that make the project understandable.

Project Organisation

Choose a page to see which CSS files it loads

Shared CSS can be reused, while page and feature files are linked only where they are useful.

Home page loads common.css and home.css. It does not load sales.css, gallery.css, or gallery-grid.css.

gallery-grid.css is a feature-specific example. Only a page that uses that gallery-grid feature needs to link it.

More files do not automatically mean better organisation. Split CSS when the separation has a useful purpose.

Why not load every file on every page?

The Sales page usually needs common.css and sales.css, not home.css. This keeps the page's links relevant and can avoid loading page-specific styling it does not use. Organisation is the main benefit; splitting files does not automatically make a website faster.

Stylesheet Order

Shared CSS usually comes before page-specific CSS

If two stylesheets try to change the same thing, their order can sometimes affect which style you see.

common.css
body {
  background-color: lightblue;
}
home.css
body {
  background-color: lightyellow;
}

Change the link order

Both files use the same kind of pre-written rule so the effect of order is easy to see.

index.html

Page result

Later, you will learn exactly how the browser decides which CSS rule wins. For now, remember the useful convention: shared/general CSS first, then page-specific CSS.

Problem Solving

Trace the link from the current HTML file

Problem 1 · wrong folder
<link rel="stylesheet" href="common.css">

From index.html, this looks beside the HTML file. The real file is inside css/.

Fix: href="css/common.css"
Problem 2 · missing ../
<link rel="stylesheet" href="css/common.css">

From pages/sales.html, this looks for pages/css/common.css.

Fix: href="../css/common.css"
Problem 3 · wrong rel
<link rel="style" href="css/common.css">

The browser needs rel="stylesheet" to understand the resource's relationship to the page.

Problem 4 · wrong location
<body>
  <link rel="stylesheet" href="css/common.css">
  <h1>Sales</h1>
</body>

Move the stylesheet link into the document <head>.

Problem 5 · wrong filename
<link rel="stylesheet" href="css/commons.css">

The folder contains common.css. Paths and filenames must match the real file.

CSS link checklist

  1. Is the <link> inside <head>?
  2. Is rel="stylesheet" correct?
  3. Does the filename match?
  4. Is the path correct from this HTML file?
  5. If the page is inside another folder, do you need ../?
  6. Are you editing the CSS file this page actually links?

Glossary
Quick glossary

          

            
CSS
A language used to control how web content looks.

            
Stylesheet
A CSS file that supplies styling to a page.

            
Link
A void element that connects the HTML document to another resource.

            
Rel
The attribute describing the linked resource's relationship to the page.

            
Href
The attribute containing the CSS file's location.

            
Shared CSS
Styling reused by multiple pages.
