32 · Collecting and processing data

Common exam mistakes

“Data = information”

Reveal the correction

Data consists of recorded facts or values; information gives data meaning for a purpose.

“Validation proves correctness”

Reveal the correction

It checks rules, not real-world truth.

“Sorting changes the values”

Reveal the correction

It changes record order. Fields stay together.

“Aggregation = analysis”

Reveal the correction

Aggregation summarises values; analysis identifies patterns or meaning.

“Reporting means charts only”

Reveal the correction

Tables, dashboards, alerts and summaries are also reports.

“Collection always needs a person”

Reveal the correction

Sensors and software systems can collect data automatically.

Exam-style practice

Write an applied explanation, then compare it with the guide. These are practice questions, not an official mark scheme.

Draft answers save automatically in this browser.

4 marks

Question 1

Explain how hardware and software could work together to collect temperature data.

Show answer guide
  • Explain that a sensor captures temperature and supplies a value, rather than simply naming a sensor.
  • Explain how software reads that value and attaches a timestamp or sensor ID, making readings comparable.
  • Link validation and storing the record to a usable dataset. Develop two linked hardware/software points for up to four marks.
4 marks

Question 2

Explain the difference between validation and sorting, using weather records.

Show answer guide
  • Validation tests a rule: 91°C fails the station’s range check and is flagged for investigation.
  • Sorting orders complete records by a field, such as timestamp, without altering temperatures.
  • For four marks, explain each function and apply each to the records. Neither proves a reading is true.
6 marks

Question 3

Explain how aggregation and analysis could be used by a supermarket to process sales data.

Show answer guide
  • Aggregation could total sales by product and day, turning individual transactions into comparable summaries.
  • Analysis could compare these summaries to identify products consistently selling fastest on Fridays.
  • Link the pattern to planning stock or staffing. Explain why the total alone does not explain a cause. Develop three applied links for up to six marks.
8 marks

Question 4

Analyse how a college could collect and process attendance data to produce useful information.

Show answer guide
  • Teachers could enter attendance in a form, or a reader could capture student IDs; software adds lesson and time.
  • Validate required IDs/statuses and flag incomplete entries. A valid ID does not prove the student attended.
  • Sort by student/date; aggregate absences or attendance percentages over a suitable period. Analyse recurring absence patterns.
  • Report a table or exception summary to tutors so they can follow up. For stronger answers, connect collection choices, processing and decisions; explain that attendance records alone cannot establish reasons for absence.
10 marks

Question 5

A transport company collects GPS, journey-time and passenger data from hundreds of vehicles. Discuss how processing functions could turn raw data into useful information for managers.

Show answer guide
  • GPS receivers capture locations; ticketing/passenger systems record counts; software timestamps and links readings to journeys.
  • Validate plausible locations, times and counts. Flag failures; a value passing validation is not necessarily accurate.
  • Sort by vehicle and timestamp; convert units or time formats when sources differ so comparisons are meaningful.
  • Aggregate journey times and passenger counts by route or period. Analyse repeated delays and busy services, then investigate possible causes using further evidence.
  • Choose reports for managers: route comparisons for scheduling and exception alerts for unusual delays. Link each choice to decisions such as allocating vehicles.
  • For higher marks, discuss trade-offs: summaries reveal patterns but hide individual journeys; suspect readings can distort averages. Justify selected functions and formats for this purpose rather than listing all six definitions.

Glossary

Quick glossary

Data
Recorded facts or values.
Raw data
Data as collected, before processing for the current task.
Log
A record of events in a system.
Information
Data processed or presented meaningfully.
Sorting
Ordering records by a chosen field.
Analysis
Identifying patterns, trends, relationships or anomalies.
Validation
Checking whether data follows set rules.
Aggregation
Combining values into totals or summaries.
Conversion
Changing data into another form or unit.
Reporting
Presenting processed information clearly.

Choose the tools

  • Useful outputs help users make decisions.
