What a stack frame contains

Each call has a frame containing information needed to run the call and return to its caller. Details depend on the language and runtime. Repeated calls to the same function can have separate frames.

Arrival order and urgency are different rules

A plain FIFO queue chooses by arrival time. Some systems need an explicit priority rule instead.

Plain FIFO

The 09:00 report is taken first.

A priority policy

The critical alert may be taken first because of its assigned priority.

With several workers, jobs taken in arrival order can finish in a different order because they take different amounts of time.

Policies in real services

Real services choose policies for their requirements. Priority, retries and re-delivery can affect ordering; “queue” in a product name does not guarantee strict FIFO.

Use the operations to express your intention

These short examples are pseudocode: readable descriptions of a program, rather than a particular programming language.

Record and reverse an edit

history.push(editRecord)
action = history.pop()
reverse(action)

editRecord includes the change and its previous state, such as the previous highlighting. pop() removes and returns this record.

Accept and take a job

waiting.enqueue(fileRecord)
job = waiting.dequeue()
scan(job)

fileRecord identifies the uploaded file. dequeue() removes and returns the oldest waiting job, ready for scanning.

Here, = keeps the returned item under a name. The program then uses that item to reverse an edit or scan a file.

Using a library

Library method names vary. Read which end is used, whether an operation removes an item, and how empty or full states are handled. The stack or queue rule can be implemented using different underlying storage structures.

Data structures

Handle empty and full states deliberately

Operations need a defined result even when an item cannot be added or removed.

Empty

Nothing to remove or peek at

An attempt to remove from an empty structure is an underflow condition.

A program can report that it is empty, wait where appropriate, or check before removing.

ABCDE

A bounded structure is full

An extra item would exceed its capacity: an overflow condition.

A program needs a policy, such as rejecting the addition or waiting for space.

Our explorers use a capacity of five. Other implementations can have different limits or grow dynamically; memory is still finite.

Data structures

Check the rule, the operation and the result

“Peek removes the next item.”

Peek reads it without removal. Pop or dequeue removes it and returns it.

“A stack sorts values from largest to smallest.”

A stack uses addition order, not numerical size or importance. The newest item is at the top.

“A dequeued scan job is finished.”

It has left the waiting queue. A worker still has to process it.

“Every real queue always serves the first arrival first.”

Plain FIFO uses arrival order. A priority queue uses a different selection rule, and multiple workers can finish jobs out of order.

Written practice 1: Explain a simple Undo feature

4 marks · practice estimate

A drawing app records three actions in this order: Add circle, Move circle, Recolour circle. It uses a stack for a simple Undo feature. State which two actions are reversed when Undo is used twice, explain why the order fits a stack, and describe what the app must store to make an action reversible.

Show answer guidance
  • The first Undo reverses Recolour circle; the second reverses Move circle.
  • A stack is last in, first out: the most recently recorded action is available at the top.
  • Undo removes or steps back past the most recent reversible action before reaching the earlier action below it.
  • A record needs enough information to reverse the change, such as the previous colour or previous position. A label alone does not perform the reversal.

Written practice 2: Follow nested function calls

4 marks · practice estimate

A function is a named piece of work. openFile calls checkFile, and checkFile calls readHeader. The program pauses inside readHeader; none of the three calls has finished. Explain the order of these call-stack frames from top to bottom, what happens when readHeader returns normally, and how this view can help a developer investigate a problem.

Show answer guidance
  • The order from top to bottom is readHeader, checkFile, openFile: the most recently started unfinished call is on top.
  • A frame holds information about one function call, including information needed to continue its work and return to its caller.
  • When readHeader returns, its frame is removed and checkFile resumes. openFile remains waiting.
  • A developer can see the current call chain and inspect relevant frames to investigate how execution reached this point. This is not a list of every function that has ever run.

Data structures

Written practice 3: Choose a queue for file scanning

6 marks · practice estimate

A service accepts uploaded files and keeps them unavailable while checks run. In this simplified design, one worker takes equally urgent jobs in arrival order. It is already scanning A; B then C are waiting, and D now arrives. Recommend a data structure for the waiting jobs, state the next two jobs the worker should take, and explain one benefit and one limitation if uploads arrive in a burst.

Show answer guidance
  • Use a FIFO queue for the waiting jobs, so the earliest waiting arrival is selected first.
  • D is enqueued at the rear behind B and C. A is already being processed and is no longer a waiting job.
  • The next two jobs dequeued are B, then C; D waits behind them.
  • The queue buffers a short burst while the worker handles jobs at its own rate, separating arrival from processing.
  • The queue uses storage and jobs wait. If arrivals remain faster than processing, the backlog grows; a finite queue needs a stated full policy.
  • The queue organises work; scanning and the other checks assess files. Merely being queued or finishing one scan is not a guarantee that a file is safe.

Glossary

Quick reference

Data structure
A way to organise data and define how it can be accessed or changed.
Stack / LIFO
A collection where the last item added is the first item removed.
Push / pop
Push adds an item to the top of a stack. Pop removes and returns the top item.
Peek
Read the next available item without removing it: the top of a stack or front of a queue.
Queue / FIFO
A collection where the first item added is the first item removed.
Enqueue / dequeue
Enqueue adds an item at the rear. Dequeue removes and returns the item at the front.
Call-stack frame
Information about one unfinished function call in the simple nested-call model.
Buffer
Temporary storage that holds data or work until another part of a system is ready to handle it.
Capacity
The maximum number of items a particular structure is configured or able to hold.
Priority policy
A rule that selects items using their priority rather than only their arrival order.
