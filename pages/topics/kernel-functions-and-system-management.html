04 · Kernel functions

Program vs process

  1. Program on SSD
    browser.exe — stored instructions
  2. Open the application
    The OS creates a running instance
  3. Process in memory
    Browser work can receive CPU time

One program can have more than one running instance. Modern browsers may use several processes.

05 · Kernel functions

Starting a program

You open a web browser. What must happen before its window is usable?

Read the full sequence: Open the browser
  1. Program on SSD. The browser program is stored software; it is not yet this running process.
  2. Read the program. The user opens the browser. The OS reads the instructions and data it needs from storage.
  3. Allocate RAM. The kernel allocates working memory for the new process.
  4. Create a process. The OS creates a running instance and records its resources. These setup tasks may overlap in a real OS.
  5. Assign CPU time. The kernel schedules work from the process so its instructions can execute.
  6. Browser ready. The browser becomes usable. The kernel continues managing its resources while it runs.
Teacher prompt

Pause after RAM allocation: has receiving memory alone executed the program?

06 · Kernel functions

Running and ending a process

Read the full sequence: Run, close, release
  1. Process active. The kernel tracks memory, CPU scheduling, open files and hardware requests.
  2. Process ends. Work from this process is removed from scheduling; its files and other resources are released.
  3. Memory reclaimed. Its allocated RAM becomes available again. The stored program remains on the SSD.

07 · Kernel functions

Why can’t programs control everything?

Imagine a random game could…

Overwrite RAM

Destroy the editor’s unsaved assignment.

Rewrite storage

Damage files belonging to other users.

Disable protection

Bypass checks intended to keep data safe.

Reconfigure hardware

Disrupt devices used by the rest of the system.

Why is unrestricted access dangerous?

Applications need limits. A mistake in one program should not give it control of the whole system.

09 · Kernel functions

Kernel mode and system calls

Kernel mode permits privileged code to manage memory, control hardware and perform protected operations.

Read the full sequence: A protected request
  1. Restricted application. Normal application code runs in user mode. It cannot simply perform protected hardware operations.
  2. Request an OS service. A system call provides a controlled entry to privileged OS code; the application does not gain unrestricted access.
  3. Handle the operation. Kernel code checks the request and performs the permitted protected work.
  4. Return a result. The application receives success, data or an error and continues in user mode. Real calls may wait or complete asynchronously.
Teacher prompt

A system call is a controlled request, not permission for the application to do anything it likes.

10 · Kernel functions

What is an interrupt?

The CPU is busy playing music. Then you press a key. How does the event get attention?

  1. CPU is working
  2. An event signals for attention
  3. CPU temporarily handles the event
Key press Network data arrives Timer event

An interrupt is a signal that causes the CPU to temporarily deal with an event. Interrupt does not mean error. Signals can originate from hardware, including internal timers; software can also trigger interrupt mechanisms.

11 · Kernel functions

Interrupt handling, step by step

Read the full sequence: Handle a keyboard interrupt
  1. Process running. The CPU is executing work from the music process.
  2. Interrupt received. A key press is reported through the input hardware. The signal requests CPU attention.
  3. Save the current state. Enough state is preserved to resume the interrupted work later; the whole program is not reloaded.
  4. Run the handler. The CPU executes the appropriate interrupt handler.
  5. Deal with the event. The input event is acknowledged and passed on for processing. Some work may be deferred.
  6. Restore state. The saved state is restored for the interrupted work in this simplified sequence.
  7. Resume work. The music process continues. An interrupt is a normal event, not necessarily an error.
Teacher prompt

Pause at saved state: why must the CPU remember where it was? Register detail belongs in the later architecture lesson.

14 · Kernel functions

Allocating RAM

Read the full sequence: Allocate working memory
  1. Available RAM. The OS already uses some RAM. The labelled free blocks are available.
  2. Open Browser. The kernel allocates three model blocks to Browser.
  3. Open Music. Music receives its own model blocks.
  4. Open Editor. Editor receives memory; existing allocations are tracked.
  5. Open Game. Game receives the remaining blocks in this model. Real allocation sizes vary.
Teacher prompt

The blocks show ownership, not physical addresses or a particular allocation scheme. Do not introduce paging here.

15 · Kernel functions

Protecting and reclaiming memory

Read the full sequence: Protect and reclaim RAM
  1. Separate allocations. Each process has allocated memory. Colour and labels identify the owner in this model.
  2. Block an invalid write. Game tries to overwrite Browser memory. OS and hardware protection restrict this unauthorised access.
  3. Editor closes. The kernel reclaims Editor memory. Other applications keep their allocations.

16 · Kernel functions

What is multitasking?

Spotify: music Chrome: research Word: notes

How can all three seem to run at once?

The OS schedules work from processes, allocating CPU time so several applications make progress. A ready process can take a turn when another waits for input or storage.

17 · Kernel functions

CPU time slicing

Read the full sequence: Share one CPU core
  1. Ready to share. Follow the slices from left to right. Equal widths are illustrative, not a scheduling rule.
  2. Slice 1: Browser. The core now executes work from Browser. Other ready work waits for CPU time.
  3. Slice 2: Music. The core now executes work from Music. Other ready work waits for CPU time.
  4. Slice 3: Editor. The core now executes work from Editor. Other ready work waits for CPU time.
  5. Slice 4: Browser. The core now executes work from Browser. Other ready work waits for CPU time.
  6. Slice 5: Download. The core now executes work from Download. Other ready work waits for CPU time.
  7. Slice 6: Music. The core now executes work from Music. Other ready work waits for CPU time.

Switching happens quickly. Applications appear to run concurrently even when one core is taking turns.

21 · Kernel functions

Disk access: coordinate competing requests

Read the full sequence: Coordinate storage access
  1. Two requests. The editor wants to save while the browser is downloading. Both need storage access.
  2. Check and coordinate. The OS checks access and may queue requests. Applications do not independently command the SSD.
  3. Perform storage work. The storage stack carries out a request. Other requests remain coordinated.
  4. Report completion. The OS reports a result to the requesting application. The order here is illustrative.

  2. File-system catalogue / index

A file system is the structure used to organise and locate stored data. It gives meaningful names and folders to data held on storage.

24 · Kernel functions

Opening and saving a file

Read the full sequence: Open coursework.docx
  1. Ask for a named file. The application requests Documents/coursework.docx.
  2. Find file information. The file system locates its directory entry and data locations; access is checked.
  3. Read the data. The wider storage and driver stack requests a read from the device.
  4. Return file data. The data is made available to the application in memory.
Read the full sequence: Save coursework.docx
  1. Send changed data. The application asks the OS to save its data.
  2. Organise the file. File-system code determines allocation and updates relevant metadata.
  3. Request the write. The storage and driver stack arranges writes of file data and metadata.
  4. Return a result. The OS reports the outcome. Buffering can separate a returned result from durable storage.
Teacher prompt

Follow one pipeline at a time. File-system organisation and the physical device operation are different parts of the same job.

25 · Kernel functions

FAT32 and NTFS: two file-system examples

Same purpose: organise files. Different capabilities.
Feature FAT32 NTFS
Typical use Simple, widely compatible; found on removable media Common on modern Windows system drives
Individual files Limited to just under 4 GiB per file Supports much larger files and volumes
Permissions No NTFS-style file access-control lists Supports file/folder access permissions
Recovery support No metadata journaling Metadata journaling helps restore file-system consistency

FAT32 and NTFS are examples, not the definition of a file system. Journaling does not replace a backup.

Device drivers translate requests

Read the full sequence: Translate a print request
  1. General request. An application asks to print without knowing every printer model.
  2. Driver prepares commands. The appropriate driver translates the OS request into communication supported by this device.
  3. Hardware responds. The printer receives suitable commands and produces the page.

31 · Kernel functions

What happens when you save an image?

The image editor is open, music is playing, and you click Save. Connect the mechanisms you have learned.

Read the full sequence: Save an image while music plays
  1. Image editor is a process. The editor is already running; the music player is another process.
  2. Image data occupies RAM. The kernel tracks the memory allocated to the editor and music player.
  3. Share CPU time. Work from Editor and Music takes turns on this model core.
  4. Application in user mode. The editor cannot directly command protected storage hardware.
  5. Request a save. The editor uses an OS service, conceptually entering via a system call.
  6. Handle protected work. Kernel code checks the request and coordinates the permitted operation.
  7. Organise the file. File-system code determines where data belongs and which metadata needs updating.
  8. Request disk access. The OS coordinates this write with other storage requests.
  9. Communicate with the SSD. The storage driver and controller carry the operation to hardware.
  10. Completion event. The device may signal completion using an interrupt; the OS handles that event.
  11. Return to the application. The OS reports the outcome and application work continues. Music remains a separately managed process.

Conceptual sequence: real systems can overlap, buffer or defer work. A completion report is not always a guarantee that data has reached durable storage.

Teacher prompt

Pause before each highlighted mechanism and ask why it is needed. Do not infer that music stops for the whole save operation.

33 · Kernel functions

Common mistakes

Interrupt = error

Interrupts are normal signals for events; they need not indicate a fault.

Program = process

Stored software is a program; a running instance is a process.

Applications directly control hardware

Applications normally request OS services for protected operations.

Multitasking = everything executes simultaneously

A single core may rapidly take turns. Separate cores can run work simultaneously.

File system = hard drive

The file system organises stored data. The drive is physical hardware.

Driver = ordinary application

A driver supports OS-to-device communication; it is not the user’s general-purpose app.

More kernel access is always better

Restricted user mode helps protect the OS and other processes.

4 marks Explain

Question 1

Explain how the kernel manages program execution when an application starts.

Show answer guide
  • Explain that needed instructions/data are read from storage so the program can be used.
  • Connect RAM allocation to holding the process’s active instructions and data.
  • Explain that a process is created and its resources are recorded.
  • Connect CPU scheduling to executing work so the application becomes usable.
4 marks Explain

Question 2

Explain what happens when an interrupt occurs while the CPU is running another process.

Show answer guide
  • The signal requests attention, so current work is temporarily interrupted.
  • Relevant state is saved so the interrupted work can later continue correctly.
  • The appropriate handler runs to deal with the event.
  • State is restored and work resumes in the simplified sequence. Explain the connections, not just the names.
6 marks Explain

Question 3

Explain how memory management and multitasking allow several applications to run effectively.

Show answer guide
  • Allocation gives each process working memory for its instructions and data.
  • Tracking free/used RAM allows the OS to coordinate competing needs.
  • Protection limits one process corrupting another; reclamation makes released RAM available again.
  • Scheduling shares CPU time so several processes make progress.
  • Rapid switching gives concurrency on one core; separate cores may execute work simultaneously.
  • Connect the two: a process can retain RAM while waiting for its next CPU turn. Credit developed cause-and-effect links rather than six isolated terms.
8 marks Analyse

Question 4

Analyse the role of the OS when a user opens, edits and saves a document while other applications are running.

Show answer guide
  • Connect opening the application to loading, process creation, RAM and scheduled CPU work.
  • Distinguish opening a named document through the file system/storage stack from starting the application.
  • Explain how memory protection and CPU scheduling keep editing and other applications progressing.
  • Connect user-mode editing to a controlled save request and permission checks.
  • Link file-system locations/metadata to coordinated disk access and the driver/device operation.
  • Explain how input or completion interrupts request attention without necessarily ending the editor.
  • Analyse outcomes: responsive use and protected data, but finite RAM/CPU/storage can cause contention.
  • Build a coherent open → edit → save explanation with consequences in this context; do not award a full answer for a list of definitions.
12 marks Discuss

Question 5

Discuss how kernel functions allow a modern computer to run multiple applications safely and efficiently.

Show answer guide
  • Build a connected explanation of program execution, memory, scheduling, interrupts, modes, file systems, disk access and drivers.
  • Explain safety: privilege boundaries and protected memory limit damage; controlled file/device requests help enforce access.
  • Explain efficiency: scheduling shares CPU work, allocation/reclamation reuses RAM, and event handling responds to devices.
  • Use a sustained example such as an editor saving while music plays to connect mechanisms.
  • Balance the discussion: switching and checks have overhead; resources are finite; privileged faults can affect the wider system.
  • Distinguish the wider OS responsibilities for accounts/network services from the specification’s kernel list.
  • Conclude with a supported judgement about safe, efficient sharing. Definitions alone are limited; developed relationships, application and evaluation make a stronger answer.

Glossary

Quick glossary

Program
Stored software instructions.
Process
A running instance of a program.
System call
A controlled request for an operating-system service.
Scheduling
Allocating CPU time to ready work.
Kernel
The core part of the operating system that controls resources and system tasks.
Interrupt
A signal that requests attention from the CPU.
User mode
A restricted mode used by ordinary applications.
Kernel mode
A privileged mode used for low-level OS operations.
File system
The method used to organise, address, save, and retrieve files on storage.
Device driver
Software that allows the OS to communicate with hardware.

Remember

Name the control

  • Programs request work; the kernel controls access.
  • Interrupts ask for CPU attention.
  • User mode is restricted; kernel mode is privileged.
  • File systems organise data; drivers support device communication.
