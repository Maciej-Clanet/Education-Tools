An array gives each element a numbered position

In this model, an array has a fixed number of elements of one data type. An index identifies each position.

failedLogins[3]→12

Index 3 selects the fourth element.
The stored value is 12.

Length 6 means indices 0 to 5. An index of 6 would be outside this array.

Names vary between programming languages

This is a fixed-size, typed array model, as used by languages such as C# and Java. Some languages use the name “array” for a more flexible collection. Always check the language’s rules. These examples use zero-based indexing; not every language does.

Type names and storage

Languages may call real-number types float, double or decimal, with different range and precision. A character type holds one character in languages that provide it. A string holds text. Types also affect storage requirements; exact sizes depend on the language and representation.

Adjacent slots make a known index easy to locate

Array elements occupy consecutive, equal-width slots. The program can calculate a slot’s location from the start address and its index.

Read a known index directly. Searching for a particular value may still require checking several elements.

Why layout matters to hardware

Neighbouring array slots can make sequential processing efficient because processors fetch memory in blocks into their cache. If the elements are references to records, the references are adjacent; the records themselves need not be. The 4-byte example illustrates equal-width slots, not a universal integer size.

A flexible size does not guarantee faster operations. Match the implementation to the operations you need.

Processor work and memory locality

Array slots support direct indexed access and place neighbouring entries together, which often helps when scanning them in sequence. Middle insertions can move many entries. Linked traversal reads references to locate later nodes; scattered nodes can make less effective use of a processor’s cache. Actual performance also depends on the implementation and workload.

Recognising these choices in security work

Security tools collect events, search results and device measurements. Their memory usage and responsiveness depend partly on these choices. When reviewing code, check that an index lies within the collection’s bounds and that growing input is handled sensibly. “Fixed size” is not permission to read beyond the last element.

Arrays, lists and data types

Separate position, value, type and layout

“Index 3 means the third item.”

In these zero-based examples, index 3 is the fourth item. Index and stored value are different things.

“Fixed-size arrays cannot be edited.”

You can replace an element. The number of elements stays fixed.

“Lists always use links and allow mixed types.”

A list may be array-backed or linked. Its type rules are a separate choice.

“Linked lists are always best for frequent changes.”

Changing links can be local when the position is known. Finding that position may require traversal, and each node needs reference storage.

A security dashboard stores 24 whole-number failed-login counts, one for each hour from 00:00 to 23:00. Explain why a fixed-size array is suitable. State the element type and the zero-based index for 17:00.

Show answer guidance
  • An integer stores a whole-number count.
  • The number of hourly slots is known: 24.
  • The program can read or update a particular hour directly by its index, without following earlier entries.
  • 17:00 is at index 17 because 00:00 is at index 0. Updating the count leaves the array length at 24.

Written practice 2: A changing results list

4 marks · practice estimate

A file-search app discovers an unknown number of matching files. It appends each match and lets the user select a result by index. Explain why an array-backed list is a suitable choice, and what may happen when its backing array is full.

Show answer guidance
  • The list can grow as more matches are found; its logical count need not be fixed in advance.
  • An array-backed implementation supports direct indexed access to a selected result.
  • A full backing array may be replaced by a larger one and its entries copied, so some additions involve extra work.
  • Spare capacity uses memory. The app can usually use a library list rather than implement resizing itself.

Written practice 3: Explain a linked insertion

4 marks · practice estimate

A singly linked list contains A → C → D. A program already has a reference to node A and inserts a new node B after it. Explain the link changes, one benefit compared with inserting into an array-backed list, and one cost of linked storage.

Show answer guidance
  • Set B’s next reference to C, then set A’s next reference to B. The resulting order is A → B → C → D.
  • C and D can remain in their existing locations; their entries do not need to shift to make a gap.
  • Each node needs storage for a next reference as well as its value.
  • Access by position requires following links. If A were not already known, locating it could also take traversal.

Glossary

Quick reference

Array
In our main model, a fixed number of elements of one type, stored in adjacent equal-width slots and accessed by index.
Element
One item in a collection.
Index
A position used to identify an element. These examples count from zero.
Data type
Defines the kind of value and the operations allowed on it.
Record
A group of named fields, which can have different data types.
List
An ordered collection. Our list model supports adding and removing items; the storage implementation can vary.
Array-backed list
A list that keeps its entries in an underlying array, replacing that array when more capacity is needed.
Count / length
The number of elements currently in a collection.
Capacity
The number of entries the current storage can hold before it needs to grow.
Linked list
A list implemented using nodes connected by references.
Node
A value or reference to an item, together with link information.
Head
A reference to the first node in a linked list.
Next reference
A link identifying the next node; an empty reference marks the end in this example.
Traversal
Visiting nodes in sequence by following their links.
