Your first Python API

Build a backend you can test

Start with a greeting, then add two practice endpoints that receive data. You will test everything in your browser before connecting a frontend.

You need Python 3.10 or newer, VS Code and basic Python familiarity. Use What is a backend? for a recap of requests and responses.

No database is needed for this lesson.

Step 2 · Project tools

Why use a virtual environment?

A package is reusable Python code. A virtual environment, or venv, gives one project its own place to install packages.

Both projects still run on your computer. A venv keeps their Python tools separate.

Create it once; activate it when you work

In the project terminal, run the two lines for your system, one at a time.

Windows · PowerShell

PowerShell 
py -m venv venv
.\venv\Scripts\Activate.ps1

macOS / Linux

bash or zsh 
python3 -m venv venv
source venv/bin/activate

Line 1 creates the venv folder. Line 2 activates it so this terminal uses the project’s environment.

Step 3 · Packages

FastAPI

A Python framework: ready-made tools for building an API.

It connects requests to your functions and turns their results into responses.

pip

Python’s package installer.

It downloads and installs packages so your Python code can import and use them.

Install the tools for this backend

With the venv active, run:

Step 4 · First code

Write a function that answers a request

Save this in main.py. A GET request asks for data; / is the root path.

main.py · first endpoint 
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def read_root():
    return {"Hello": "World"}
from fastapi import FastAPI
Bring the FastAPI tool into this file.
app = FastAPI()
Create the application and name it app.
@app.get("/")
Connect GET requests for / to the function immediately below. This line is called a decorator.
def read_root():
Define the function. FastAPI calls it when that request arrives.
return {"Hello": "World"}
Send back a Python dictionary. FastAPI converts it into JSON. Keep this line indented.

Step 5 · Start the server

Read the server command from left to right

Save main.py, then run this in the active venv from the folder containing that file:

Terminal · start Uvicorn 
python -m uvicorn main:app --reload --port 8001

python -m

Use this environment’s Python to run a module.

2

The server program that listens for requests.

3

main:app

Find main.py and use the app created inside it.

4

--reload

Restart when you save code changes while developing.

5

--port 8001

Listen on port 8001, which we will use in the browser address.

Wait for “Application startup complete”. Leave the terminal running while testing. Press Ctrl + C to stop the server.

Save the installed versions

Restore on another computer

Terminal · restore packages

Commit requirements.txt with your code. Run freeze again after installing more packages. Recreate the venv instead of copying its folder.

A shared job

Middleware works around your endpoints

Suppose you want to measure how long every request takes. Putting the same timer inside every endpoint would repeat code.

Middleware is a shared layer that can run before an endpoint and after it returns a response.

Another possible job

Record which path was requested, such as /auth/register.

The job we will use

Add browser permission information with FastAPI’s ready-made CORS middleware.

Browser permissions

Why does a frontend need permission?

Your frontend and backend have different addresses. The browser checks whether frontend JavaScript is allowed to read a response from another origin.

An origin is the protocol, hostname and port, for example http://localhost:5173. Changing any of those makes a different origin.

The built-in /docs page uses the backend’s own origin, so it can test the API without this extra permission. CORS does not log anyone in or make an API private.

Step 8 · Use ready-made middleware

Add CORS to main.py

Add the import at the top. Add the middleware block after app = FastAPI(), before @app.get("/").

main.py · new import 
from fastapi.middleware.cors import CORSMiddleware
main.py · CORS settings 
app.add_middleware(
    CORSMiddleware,
    allow_origins=[
        "http://localhost:5173",
        "http://127.0.0.1:5173",
    ],
    allow_methods=["GET", "POST"],
    allow_headers=["Content-Type"],
)
app.add_middleware(...)
Use the ready-made CORSMiddleware.
allow_origins
The frontend addresses allowed to read responses. Use your actual port if it differs; leave out page paths such as /about.
allow_methods
Allow GET requests for data and POST requests that send data.
allow_headers
Allow the Content-Type label used when sending JSON.

Step 10 · Request data

A model describes the data we expect

A request body is data sent to the backend. Our practice registration request sends an email, password and username as JSON.

Pydantic supplies these models and is installed with FastAPI. A model is a description in Python code, not a database table.

These are practice form requests. Use made-up values. The examples do not create accounts, save passwords or log anyone in.

Write the two request models

Save this in models/auth_models.py:

models/auth_models.py 
from pydantic import BaseModel

class RegisterForm(BaseModel):
    email: str
    password: str
    username: str

class LoginForm(BaseModel):
    email: str
    password: str
BaseModel
Pydantic’s starting point for describing and checking data.
class RegisterForm(BaseModel):
Define a model named RegisterForm, using Pydantic’s checking behaviour.
email: str
Field name on the left, type on the right. str means text. All fields shown are required because no defaults are provided.
LoginForm
A second shape: email and password, without username.

email: str checks for text; it does not prove that an email address exists or that someone owns it.

Step 11 · Related endpoints

Start a router for these functions

An APIRouter collects related endpoints. Start routes/auth_routes.py with:

routes/auth_routes.py · start of file 
from fastapi import APIRouter
from models.auth_models import LoginForm, RegisterForm

auth_router = APIRouter()
from fastapi import APIRouter
Import the tool for grouping endpoints.
from models.auth_models import ...
Bring in the two models from models/auth_models.py. Dots separate the folder and file names.
auth_router = APIRouter()
Create a router and name it auth_router. We will add two functions below it.

We will attach this router to app after writing the functions.

Registration practice: receive data and reply

Add this function below auth_router = APIRouter() in the same file:

routes/auth_routes.py · append register() 
@auth_router.post("/register")
def register(register_data: RegisterForm):
    data = register_data.model_dump()
    return {
        "message": "Practice request received",
        "email": data["email"],
        "username": data["username"],
    }
@auth_router.post("/register")
Connect a POST request for this route to the function below. POST lets us send a body.
register_data: RegisterForm
FastAPI checks the body using RegisterForm, then passes that data into the parameter register_data.
data = register_data.model_dump()
Convert the model’s data to a normal Python dictionary named data.
return {...}
Build the response. data["email"] reads one dictionary value. We return the message, email and username.

The dictionary from model_dump() contains all the model’s fields. The response contains only the fields we write in return.

Login practice: read a model field directly

Add this second function below register() in the same file:

routes/auth_routes.py · append login() 
@auth_router.post("/login")
def login(login_data: LoginForm):
    return {
        "message": "Practice only; no login performed",
        "email": login_data.email,
    }
@auth_router.post("/login")
Add another POST route to the same router.
login_data: LoginForm
This function expects the email and password fields from LoginForm.
login_data.email
Read the email directly from the model. You do not need a dictionary to read one field.
The returned message
Makes clear that this is a practice response. No password is checked and no login happens.

Step 12 · Connect the pieces

Import the router, then attach it

In main.py, import the router with the other imports, then include it after the CORS settings:

main.py · two additions 
from routes.auth_routes import auth_router

app.include_router(
    auth_router,
    prefix="/auth",
    tags=["Auth"],
)
from routes.auth_routes import auth_router
Find routes/auth_routes.py and bring its auth_router into this file.
app.include_router(auth_router, ...)
Register this router’s endpoints with the running app. Saving a route file alone does not connect it.
prefix="/auth"
Put /auth before every path in this router.
tags=["Auth"]
Group these endpoints under the heading “Auth” in /docs. A tag does not change the URL.

Assemble the final main.py

This is the complete file. Compare it with yours, or copy it to replace main.py.

main.py · complete app 
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
from routes.auth_routes import auth_router
app = FastAPI()
app.add_middleware(
    CORSMiddleware,
    allow_origins=[
        "http://localhost:5173",
        "http://127.0.0.1:5173",
    ],
    allow_methods=["GET", "POST"],
    allow_headers=["Content-Type"],
)
app.include_router(auth_router, prefix="/auth", tags=["Auth"])
@app.get("/")
def read_root():
    return {"Hello": "World"}
1 · Import the tools and router
The router import comes from the file you just created.
2 · Create and configure the app
FastAPI() creates the app; add_middleware adds the CORS settings.
3 · Attach the router
include_router adds its endpoints, prefixes their paths with /auth and groups them under Auth in the docs.
4 · Keep the greeting
read_root() still answers GET /.

When something does not work

Server or import problem

No module named fastapi or uvicorn
Activate this project’s venv, then install the lesson’s packages.
Cannot import main
Run from the folder containing main.py. Use main:app, without .py.
Address already in use
Stop an old server you started, or choose a free port and use that port in the browser too.

Request problem

404 · Not found
Check the full path and that the router is included.
405 · Method not allowed
A browser address bar sends GET. Test a POST route with /docs.
/docs works but the frontend cannot read the response
Check the frontend’s actual origin against allow_origins, and check that its API address is correct.
