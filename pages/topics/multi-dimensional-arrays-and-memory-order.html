Multi-dimensional arrays and memory order

Learn how arrays extend from one dimension to many, how programs index values inside larger structures, and why row-major and column-major order change the way those values are laid out in memory.

Multiple dimensions

How many positions identify one reading?

A monitoring app records temperatures. As it records more days and more sensors, each reading needs more position information.

1D

One sensor, one day

Choose an hour.

readings[hour]
2D

Add more days

Choose a day and hour.

readings[day][hour]
3D

Add more sensors

Choose a sensor, day and hour.

readings[sensor][day][hour]

A dimension is an axis of the array. A multidimensional array has two or more dimensions; each adds an index to locate one element.

1D · One index

Choose one hour

Start with one sensor on one day. A one-dimensional array holds three hourly temperatures in °C.

Hour 011[0]
Hour 112[1]
Hour 213[2]

readings[2] → 13

Index 2 selects the third reading.

The valid indexes are 0, 1 and 2. Three elements do not mean three dimensions.

2D · Two indexes

Choose a day, then an hour

Add a second day for the same sensor. Each row is a day; each column is an hour. The readings are still temperatures in °C.

One sensor · two days × three hours
Hour 0Hour 1Hour 2
Day 0111213
Day 1212223

readings[1][2] → 23

  1. [1] selects the second day.
  2. [2] selects its third hour.

2 dimensions, a 2 × 3 shape, and 6 elements. These describe different features of the same array.

3D · Three indexes

Choose a sensor, then a day, then an hour

Add a second sensor. Each sensor has its own 2D grid of readings: the extra dimension selects a layer.

Sensor 0 · first layer
Hour 0Hour 1Hour 2
Day 0111213
Day 1212223
Sensor 1 · second layer
Hour 0Hour 1Hour 2
Day 0141516
Day 1242526

readings[1][0][2] → 16°C

Second sensor → first day → third hour. Shape: 2 sensors × 2 days × 3 hours = 12 readings. The array has 3 dimensions, not 12.

An axis can represent time or a category. “3D” does not have to mean a physical object with depth.

From grid to memory

A logical grid needs a storage order

The program uses rows and columns, but memory addresses form a linear sequence. A packed array stores equal-sized elements in consecutive slots.

Logical view · same six readings
Col 0Col 1Col 2
Row 0111213
Row 1212223

Which value follows 11?

Across the row: 12.

Down the column: 21.

A memory order chooses which neighbours are stored together.

Two common rules are row-major and column-major. Neither changes which value belongs at a particular row and column.

About this memory model

Each illustrated slot holds one element, not necessarily one byte. We use a packed numeric array; some languages implement nested collections using references instead. Index notation here is illustrative.

Row-major order

Finish one row before starting the next

In row-major order, values from a row occupy consecutive memory slots. Read across row 0, then across row 1.

Logical grid · badges show storage slots
Col 0Col 1Col 2
Row 0Slot 111Slot 212Slot 313
Row 1Slot 421Slot 522Slot 623
  1. Row 0 → 11, 12, 13
  2. Row 1 → 21, 22, 23

Column-major order

Finish one column before starting the next

In column-major order, values from a column occupy consecutive memory slots. Read down column 0, then columns 1 and 2.

Same logical grid · different storage slots
Col 0Col 1Col 2
Row 0Slot 111Slot 312Slot 513
Row 1Slot 221Slot 422Slot 623
  1. Column 0 ↓ 11, 21
  2. Column 1 ↓ 12, 22
  3. Column 2 ↓ 13, 23

Column-major: 11, 21, 12, 22, 13, 23.

Keep the ideas separate

Changing storage order does not change the grid

Stays the same

  • The array has 2 dimensions.
  • Its shape is 2 rows × 3 columns.
  • grid[1][0] still gives 21.

Changes

The sequence in memory, and therefore which elements are stored next to each other.

The program must use the matching layout rule to find the right element.

Row-major and column-major describe storage. They do not turn a 2D array into a 1D array or swap its logical rows and columns.

In software · Choose the axes

Match each index to a real part of the problem

Room-booking software

For one room, choose a week, day and period to locate a booking.

Week→Day→Period
bookings[week][day][period]

A greyscale video in memory

One frame is a 2D grid of pixel brightness values. A sequence adds a frame index.

Frame→Row→Column
video[frame][row][column]

Each complete set of indexes selects one element: a booking in one room, or a pixel brightness in one frame.

In software · Processing speed

An image filter visits millions of pixels

Suppose a greyscale image is stored in a packed row-major array. A brightness filter visits every pixel.

Visit across each row

1 → 2 → 3 → 4 → 5 → 6

On our small 2 × 3 grid, these are the memory slots visited in order.

Visit down each column

1 → 4 → 2 → 5 → 3 → 6

The same values are visited, with jumps through the stored sequence.

The CPU cache brings nearby data into fast storage together. Visiting nearby elements can make better use of that data and reduce slow memory accesses.

Neither layout is always faster: match the access pattern to the actual layout, then measure. MathWorks: layout and performance.

In software · Sharing data

A receiving program must know the layout

A sensor program sends six numbers for a 2 × 3 grid. The receiver knows the shape, but also needs the element type and storage order.

Sent in row-major order11, 12, 13, 21, 22, 23
Read as row-major · intended grid
Col 0Col 1Col 2
Row 0111213
Row 1212223
Read as column-major · wrong positions
Col 0Col 1Col 2
Row 0111322
Row 1122123

The same numbers have been interpreted with the wrong rule: grid[0][1] becomes 13 instead of 12. Agree on the layout, or convert it when transferring data.

For example, native C arrays use row-major layout; MATLAB uses column-major layout. MathWorks: array layouts and conversion.

4 marks Explain

Question 1

Explain why a three-dimensional array would be suitable for storing room bookings for different weeks, days, and lesson periods in a college timetable system.

Show answer guide

A strong answer links each dimension to a real category in the scenario.

  • The booking system needs separate positions for week, day, and lesson period.
  • A three-dimensional array provides three indexes to represent those categories.
  • The program can retrieve one booking directly by supplying all three indexes.
  • This keeps the structure organised and matches the timetable layout logically.
5 marks Describe and compare

Question 2

A 2 x 3 array stores values [ [4, 5, 6], [7, 8, 9] ]. Describe the order of values in row-major memory and in column-major memory, then explain why the logical grid is still the same in both cases.

Show answer guide

The best answers give both sequences and then explain the difference between storage layout and logical meaning.

  • Row-major order stores: 4, 5, 6, 7, 8, 9.
  • Column-major order stores: 4, 7, 5, 8, 6, 9.
  • Row-major stores one full row before the next row.
  • Column-major stores one full column before the next column.
  • The array still represents the same 2 x 3 grid logically, even though the memory sequence differs.

Glossary

Quick glossary

Multi-dimensional array
An array with two or more dimensions, using more than one index to locate an element.
Row-major order
A storage rule that places values into memory row by row.
Column-major order
A storage rule that places values into memory column by column.
Index
The position number used to identify a value inside an array.

Remember

Ask two separate questions

  • How many indexes are needed to locate the value?
  • How are the values stored in memory?
  • Those two answers are related, but they are not identical.
