Overview

What you should know by the end of this lesson

Transmission is not only about moving bits from one system to another. Sometimes the data needs to be protected from people who should not read it, and sometimes it needs to be made smaller so it can move faster or use less storage.

Encryption protects meaning

Data is transformed into ciphertext. Anyone who intercepts it should see unreadable data unless they have the correct key.

Compression reduces size

Data is represented using fewer bits. This can reduce bandwidth, transfer time, storage use, and sometimes quality.

The choice depends on the job

A medical record, streamed video, and login message do not have the same requirements. Strong answers explain the trade-off, not just the definition.

Learning goals

  • Explain simple ciphers such as Caesar and Vigenere.
  • Compare symmetric and public key encryption.
  • Explain lossy and lossless compression.
  • Judge the impact of security and compression choices.

Quick memory hooks

  • Encryption: makes data unreadable without the right key.
  • Symmetric: same key to encrypt and decrypt.
  • Public key: paired public and private keys.
  • Compression: reduces file size, but may affect quality.

Why this matters

Encryption is about confidentiality: protecting the meaning of data if it is intercepted. Compression is about efficiency: reducing the amount of data that must be stored or transmitted. They can be used together, but they solve different problems.

Encryption Basics

Simple ciphers show the basic idea of scrambling data

Simple ciphers are not strong enough for modern secure systems, but they make the core idea visible: plaintext is transformed into ciphertext using a rule and a key. To decrypt it, the receiver reverses the process with the correct key.

Plaintext MEET AT 4
+
Key shift 3
=
Ciphertext PHHW DW 4

Caesar cipher

Every letter is shifted by the same number of places in the alphabet. A shift of 3 changes A to D and CAT to FDW.

It is easy to explain, but weak because there are only 25 useful shifts to try.

Vigenere cipher

A keyword creates changing shifts. If the key is CODE, then letters use shifts based on C, O, D, E, then repeat.

This hides patterns better than a Caesar cipher, but it is still a historic teaching cipher rather than modern security.

Vigenere Square

Use a Vigenere square to encode and decode letters

A Vigenere square is a table of shifted alphabets. The keyword chooses the row. The plaintext or ciphertext letter chooses what you look for in that row.

Encoding

  1. Write the plaintext.
  2. Repeat the keyword until it lines up with each letter.
  3. Use the key letter to choose the row.
  4. Use the plaintext letter to choose the column.
  5. The intersection gives the ciphertext letter.

Decoding

  1. Write the ciphertext.
  2. Repeat the same keyword above it.
  3. Use the key letter to choose the row.
  4. Find the ciphertext letter inside that row.
  5. The column heading gives the plaintext letter.

Worked encoding example

Encode CAT using the keyword KEY. The keyword is already the same length, so each plaintext letter has one key letter above it.

Plaintext C A T
Key K E Y
Ciphertext M E R

Row K and column C meet at M. Row E and column A meet at E. Row Y and column T meet at R.

Worked decoding example

Decode MER using the same keyword KEY. This time the ciphertext is inside the row, and the plaintext is the column heading.

Ciphertext M E R
Key K E Y
Plaintext C A T

In row K, find M; its column is C. In row E, find E; its column is A. In row Y, find R; its column is T.

Exam wording

A Vigenere cipher uses a keyword to choose different Caesar shifts. With a Vigenere square, the key letter selects the row and the plaintext letter selects the column; the intersection is the encrypted letter.

System Encryption

Computer systems use key-based encryption to protect real traffic

Real systems need methods that scale beyond classroom ciphers. Unit 2 expects you to recognise the difference between symmetric key encryption and public key encryption, including the implications of how keys are shared.

Symmetric key encryption

Sender shared secret key Receiver

The same secret key encrypts and decrypts the data. It can be efficient, but both parties must already have the key or share it securely first.

Public key encryption

Public key encrypt Private key

A public key can be distributed openly. The matching private key is kept secret and is needed to decrypt the message.

Confidentiality

If encrypted traffic is intercepted, the original message should still be unreadable without the correct key.

Key management

The encryption method is only useful if keys are protected and given to the correct people or systems.

Performance

Stronger security and key exchange processes can add complexity, so systems must balance security with practical use.

How to phrase it in an exam

Symmetric encryption uses one shared secret key, so the key exchange is the main challenge. Public key encryption uses a key pair, so the public key can be shared while the private key stays secret.

Compression

Compression reduces file size, but not always in the same way

Compression can make transmission faster and storage more efficient by reducing the number of bits needed to represent the data. The key exam difference is whether the original data can be rebuilt exactly.

Lossless keeps the original

AAAABBBCC A4 B3 C2 AAAABBBCC

The stored pattern is smaller, but the exact original can be rebuilt.

Lossy removes detail

The file can become much smaller, but removed detail cannot be recovered later.

Lossless versus lossy

Type What happens to the data Typical use Implication
Lossless The original data can be rebuilt exactly. Text files, documents, code, databases Safer when accuracy matters
Lossy Some information is removed permanently. Images, audio, video where small loss is acceptable Smaller files, but reduced quality

Exam Traps

Common mistakes with encryption and compression

These questions often combine technical definitions with wider implications, so accuracy matters.

Assuming encryption compresses data

Encryption protects confidentiality. Compression reduces file size. They solve different problems.

  • Encryption is about privacy and security.
  • Compression is about efficiency and size.

Fix: State the purpose before naming the method.

Mixing up symmetric and public key encryption

Students often remember that keys are involved, but not whether the same key or a pair of keys is used.

  • Symmetric uses one shared secret key.
  • Public key uses a public and a private key.

Fix: Say "same key" or "key pair" explicitly.

Using lossy compression for exact data

Some files can tolerate lost detail, but documents, code, and many data files cannot.

  • Lossless suits files where every bit matters.
  • Lossy suits media where some reduction is acceptable.

Fix: Match the compression type to the data purpose.

4 marks Explain

Question 1

Explain why public key encryption is useful when two users need to exchange data securely but do not already share a secret key.

Show answer guide

The key idea is how the method helps with secure key exchange.

  • Public key encryption uses a public key and a private key.
  • The sender can use the public key without already sharing a secret key.
  • Only the matching private key can decrypt the data.
  • This helps protect data sent across shared or public networks.
5 marks Compare and justify

Question 2

A school needs to store text documents, photos, and training videos on a website. Compare lossless and lossy compression and justify which type is suitable for each kind of file.

Show answer guide

The best answers match the compression type to the importance of keeping every detail.

  • Text documents usually need lossless compression because exact data must be preserved.
  • Photos may use lossy compression if a small quality loss is acceptable in exchange for smaller file size.
  • Training videos also often use lossy compression because they are large and bandwidth matters.
  • Lossless preserves the original data exactly.
  • Lossy produces smaller files, but removed detail cannot be recovered.

Glossary

Quick glossary

Caesar cipher
A simple cipher that shifts letters by a fixed amount.
Symmetric key encryption
Encryption that uses the same key both ways.
Public key encryption
Encryption that uses a public and a private key.
Lossless compression
Compression that preserves the original data exactly.

Remember

Protect or reduce

  • Encryption protects confidentiality.
  • Compression reduces size.
  • Lossy compression saves space by sacrificing some detail.
