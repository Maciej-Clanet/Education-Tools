Each small group of data is sent as a unit. Units can start at irregular times.

Mark each unit

Keep time within the unit

There is no continuous shared clock between units. The receiver starts its local timing again at each start bit.

Bring the ideas together

Compare the timing methods

Question Synchronous Asynchronous start/stop example
How is timing set? Shared timing keeps the stream in step. A start bit aligns the receiver for each unit.
What must agree? Clock timing and the data format. Bit speed and the data format.
What often suits it? Large blocks or streams of data. Small units sent at irregular times.

These are useful choices, not fixed rules. A synchronous link can pause, and an asynchronous link can send units back to back.

Worked judgement

Build a reason from the situation

A machine sends a long stream of camera data to its computer.

Identify the need

Need

A large amount of data must keep moving. Repeated control bits use time that could carry image data.

Connect the feature

Feature

Synchronous transfer keeps the stream in step. It can avoid start and stop bits around each byte.

Make a judgement

Choice and condition

Use synchronous transmission for this stream to reduce repeated start/stop overhead. The equipment must support shared timing.

This is a choice about timing. It does not decide whether the data paths are serial or parallel.

Your judgement

A sensor at the far end of a greenhouse

A sensor is far from its computer. Its readings are small. Both devices support either proposed link, but the cable must be cheap and easy to install.

Which data-path method would you choose?

Compare your explanation

Serial suits the longer cable and small readings. It uses fewer data paths, so there are fewer lines to keep aligned. Parallel can send a group at once, but adds lines and timing concerns.

Your judgement

A sensor that reports a change

A simple alarm sensor sends one short reading when a door opens. There may be long gaps. Both devices support either timing method, and the data rate is low.

Which timing method would you choose?

Compare your explanation

Asynchronous transmission suits the occasional short readings. Each unit can start when it is ready. Start and stop bits add overhead, but the low data rate makes that a reasonable cost. Synchronous transmission could work, but its timing arrangement is not needed for a long stream here.

Quick recap

Keep these three distinctions clear

Serial ≠ asynchronous

Serial describes the data paths. Asynchronous describes timing.

Asynchronous ≠ no timing

The receiver still needs an agreed bit speed and a way to find each unit.

Parallel ≠ always faster

Compare the actual bit rate, distance and number of data paths.

A strong answer explains what the method changes, then connects that change to the task.

Explain the trade-off

Explain your choice. Then compare your answer with the guide.

Draft answers save automatically in this browser.

4 marks Explain

Question 1

Explain why synchronous transmission is often more suitable than asynchronous transmission for a long continuous stream of video data.

Show answer guide
  • Synchronous transmission keeps sender and receiver in step during the stream.
  • That suits data which flows continuously rather than in separate irregular bursts.
  • It avoids adding start and stop framing around each small unit.
  • This can make the transfer more efficient for large amounts of continuous data.
5 marks Compare and justify

Question 2

A manufacturer needs to send data between two components inside the same machine over a very short distance at high speed. Compare serial and parallel transmission and justify which method could be suitable.

Show answer guide
  • Parallel transmission can move several bits at the same time.
  • That can be suitable over a very short internal path.
  • Serial transmission uses simpler cabling and is easier to keep aligned over distance.
  • For a short high-speed internal connection, parallel may be justified if the extra complexity is acceptable.
  • A well-argued answer may still choose serial if it prioritises simpler design and reliability.

Glossary

Quick glossary

Synchronous transmission
Sender and receiver stay aligned using shared timing.
Asynchronous transmission
Separate units are framed with control information.
Serial transmission
Bits are sent one after another on one path.
Parallel transmission
Several bits travel at the same time on multiple lines.
Timing skew
Bits on different paths arrive at slightly different times.

Remember

Two different comparisons

  • Synchronous versus asynchronous is about timing.
  • Serial versus parallel is about the data path.
  • Good answers explain the trade-off, not just the label.
