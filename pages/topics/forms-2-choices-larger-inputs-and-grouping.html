Forms 1 Recap

Forms collect NAME -> VALUE data

Radio Or Checkbox

Change the question, change the control

Use the same idea from Forms 1: look at the data being collected. If the question expects exactly one answer, radio buttons often fit. If several answers may apply, checkboxes fit.

Initial Choices

checked and selected set initial choices

Like required, checked can appear as a boolean-style attribute. Use default selections thoughtfully; do not pre-check consent or marketing choices as a normal habit.

Initial radio or checkbox selection 
<input type="radio" checked>
<input type="checkbox" checked>
<option value="morning" selected>Morning</option>

Textarea

<textarea> is for longer written answers

A text input is good for short answers. A textarea is better when the user may need several lines, such as feedback, a message, a description, or a longer written answer.

Short response <input type="text">

Name, username, short title.

Longer response <textarea></textarea>

Feedback, message, description, longer written answer.

Textarea content and placeholder behave differently

<label for="message">Message</label>
<textarea
  id="message"
  name="message"
  rows="5"
  cols="30"
  placeholder="Write your message..."></textarea>
Current value

Text between the tags is initial content

<textarea>Write something here</textarea>

That text starts inside the control as a real value. A placeholder is only a hint and disappears once the user enters content. Either way, keep a proper label.

Common Mistakes

Most form bugs come from mismatched meaning

These mistakes are common because controls have several relationships: group names, unique ids, useful values, visible labels, and group legends.

Different radio names

<input name="delivery" type="radio" value="delivery">
<input name="collection" type="radio" value="collection">

Both can be selected because the browser sees two groups. Use the same group name.

Same id on many controls

<input id="delivery" name="deliveryMethod">
<input id="delivery" name="deliveryMethod">

Same name can be intentional. Same id is not.

No useful value

<input name="deliveryMethod" type="radio">

Give each option a useful value so the submitted data says which choice was made.

Checkboxes for exactly one answer

How would you like to pay?
[ ] Cash
[ ] Card

If exactly one method is allowed, radio buttons usually fit better.

Radio buttons for many answers

Which toppings would you like?
( ) Cheese
( ) Mushrooms
( ) Peppers

If several answers may apply, checkboxes make more sense.

Text input for a long response

<input name="feedback" type="text">

For messages or feedback, a textarea gives the user more room.

Forgetting labels

<input type="checkbox" name="extra" value="giftWrap">

New controls still need meaningful labels.

Weak legend

<fieldset>
  <legend>Options</legend>
</fieldset>

The legend should describe the group or question clearly.

Text confused with value

<option value="jp">Japan</option>

The user sees Japan, but the submitted value is jp.

Glossary

Quick glossary

Radio button
A control for choosing one option from a group.
Checkbox
A control for choosing zero, one, or many independent options.
Value
The value submitted when a control is included in form data.
Textarea
A form control for longer written answers.
Select
A form control that shows a list of options.
Fieldset
An element that groups related form controls.
Legend
A label for a group of related controls.

Remember

Choose the control to fit the question

  • Radio: one choice.
  • Checkbox: zero, one, or many.
  • Select: list of options.
  • Textarea: longer written answer.
  • Fieldset and legend explain grouped controls.
