What is awkward about this?

1110101101100011

Binary uses 0 and 1. As we saw in the previous lesson, agreed rules give these patterns meaning.

Make the pattern easier to inspect
1110 1011 0110 0011

Grouping helps us keep our place when reading or copying.

Binary suits digital hardware. Long strings of bits are harder for humans to read, copy and recognise.

Hexadecimal

Four bits give us sixteen patterns

1 bit 2 patterns
→
2 bits 4 patterns
→
3 bits 8 patterns
→
4 bits 16 patterns

Each extra bit doubles the possibilities. Four bits run from 0000 to 1111 .

A group of 4 bits is a nibble .

Could one symbol represent each of those sixteen patterns?

Hexadecimal

One symbol for each four-bit group

1110 1011 0110 0011 = EB63 in hex

One hexadecimal digit represents exactly four binary bits.

Hexadecimal (hex) writes the same bit pattern with fewer symbols. It does not change the underlying data.

Hexadecimal

Web colours: two hex digits per channel

FF R · Red 11111111
80 G · Green 10000000
00 B · Blue 00000000

In this common six-digit RGB format, each channel uses one byte: eight bits, written as two hex digits. The # introduces the colour code.

1 byte = 8 bits = 2 nibbles = 2 hex digits.

Hexadecimal

An address is easier to inspect in hex

A memory address identifies a location in memory. Here is one illustrative 32-bit address:

11010110101100101111000100101100

Group and shorten it

1101 0110 1011 0010 1111 0001 0010 1100

↓ D6B2F12C

0x D6B2F12C

0x is a common programming/debugging prefix meaning “this value is hexadecimal”. It is notation, not an extra digit.

Address widths vary. This example shows compactness, not a rule that all addresses have 32 bits.

Hexadecimal

Two hex digits make a byte easy to scan

Binary 11001010 → hex CA

Developers and diagnostic tools often show raw bytes in hex. Each pair above represents one byte; we do not need to decode what those bytes mean here.

Other places you may recognise hex

Hex notation also appears in MAC addresses, IPv6 addresses and file signatures. Their structures belong to other topics.

2F: two sixteens and fifteen ones

F = 15. Multiply each digit by the value of its position.

16s 2 ↓ 2 × 16 32
1s F ↓ 15 × 1 15
Add the contributions

32 + 15 = 47 denary

Multiply each digit by its hexadecimal place value, then add.

How do the places continue?
4096 16³ 256 16² 16 16¹ 1 16⁰

Moving one position left multiplies the place value by 16.

Hex → binary: one digit at a time

Hex 3A

Expand each digit to four bits

3A = 0011 1010

One hex digit = four bits. Keep the leading zeros inside each nibble.

3 becomes 0011 , not just 11 , so its group keeps all four positions.

Hexadecimal

Binary → hex: group from the right

1100 0111

Map the two groups

Result: C7

Group binary from the right into groups of four.

What if the first group is short?

101101 → 10 | 1101 → 0010 | 1101 → 2D

Add zeros only on the left. This preserves the value while completing the first nibble.

Hexadecimal

Denary → hex: use the binary bridge

Start with 47 denary

  1. Use the binary place values

    47 = 32 + 8 + 4 + 2 + 1

    128 0 64 0 32 1 16 0 8 1 4 1 2 1 1 1
  2. Group into nibbles

    0010 | 1111

  3. Map each group

    0010 → 2 · 1111 → F

47 denary = 0010 1111 binary = 2F hexadecimal.

Common mistakes

Spot the misconception

“The computer stores hex instead of binary.”

Incorrect. At the hardware level these data values are still binary. Hex is a compact way for humans to write their bit patterns.

“A = 1 because it is the first letter.”

Incorrect. A represents denary 10. The hex digits 0–9 already cover zero to nine.

“F = 16.”

Incorrect. F = 15. Sixteen is written 10 in hex: one sixteen and zero ones.

“One hex digit represents one byte.”

Incorrect. One hex digit represents four bits. Two hex digits represent one eight-bit byte.

“Convert the whole binary number to denary first.”

Not necessary. Group from the right into four-bit nibbles, then map each group directly to a hex digit.

“0x is part of the numerical value.”

It is a common notation prefix indicating hexadecimal. It is not an extra digit and is not always required.

Hexadecimal

Four bits at a time

1110 1011 0110 0011 = EB63

Compact notation. Exact bit pattern. Colours, addresses and raw bytes.

A = 10 · B = 11 · C = 12 · D = 13 · E = 14 · F = 15

One digit = one nibble. Two digits = one byte.

4 marks Explain

Question 1

Explain why hexadecimal is often used instead of writing long binary values directly.

Show answer guide
  • One hexadecimal digit represents four binary bits.
  • This makes long binary values shorter to write.
  • Shorter values are easier for humans to read and compare.
  • It can reduce mistakes when copying addresses, bytes, or colour values.
4 marks Demonstrate

Question 2

Describe how to convert 1100 1010 from binary to hexadecimal.

Show answer guide
  • Split the binary into 4-bit groups: 1100 and 1010 .
  • 1100 is denary 12, which is hex C .
  • 1010 is denary 10, which is hex A .
  • The hexadecimal answer is CA .
4 marks Convert

Question 3

(a) Convert hexadecimal 3A to eight-bit binary. (b) Convert hexadecimal 2F to denary. Show your working.

Show answer guide

(a) 3 → 0011; A → 1010. Answer: 0011 1010 .

(b) 2 × 16 + 15 × 1 = 47 .

For each part, one mark for the method and one for the answer.

4 marks Apply

Question 4

(a) Explain why a developer may prefer hex when inspecting a memory address. (b) Explain why two hex digits are convenient for representing one byte.

Show answer guide

(a) Hex writes the same address with fewer symbols, making it easier to inspect or copy accurately (two points).

(b) One hex digit maps exactly to four bits; two digits therefore represent all eight bits in a byte (two points).

Glossary

Quick glossary

Hexadecimal
A base 16 number system using 0-9 and A-F.
Nibble
A group of four bits.
Base
The number of different digit values used by a number system.
Place value
The value a digit has because of its position.

Remember

Four bits at a time

  • One hex digit equals one 4-bit nibble.
  • Use A-F for denary values 10-15.
  • Group binary from the right when converting to hex.
