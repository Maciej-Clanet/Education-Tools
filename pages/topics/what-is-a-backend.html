What must be decided

Is the student allowed to book? Is a place still available? Has the booking actually been saved?

The frontend handles the interface. The backend handles the shared rules and server-side work behind that interface.

Two responsibilities

The screen and the service

The frontend is the part the user interacts with: HTML structure, CSS styling and JavaScript behaviour. React helps build that interface.

The backend is application code running on the server side. FastAPI helps build a Python backend that accepts requests and sends responses.

Can they use the same language?

Yes. JavaScript can run in browsers and on servers. A language alone does not decide whether code is frontend or backend; its role and where it runs matter.

From files to running software

Stored on a host, running in a browser

A server is software that listens for requests, and the word also refers to the machine running it. The machine could be a local laptop, a college server or cloud infrastructure.

Same jobs, different locations

One laptop can run both sides

During development: your laptop

localhost and 127.0.0.1 refer back to the device using them. A port identifies a listening service on that device.

After deployment

The frontend and backend may share a host or use different hosts. Separate roles do not require separate physical computers. A cloud backend still runs on real computers.

Split the work

Feedback in the browser, rules on the server

Frontend responsibilities
  • Render cards, forms and menus.
  • Respond to clicks and keyboard input.
  • Give quick feedback for an empty field.
  • Show loading, success and error messages.
Backend responsibilities
  • Check submitted data again.
  • Check identity and permission when needed.
  • Apply rules such as capacity or prices.
  • Read and update shared records.

Both sides may validate the same field. Browser checks help the user; server checks protect the operation even if browser checks are bypassed.

What else can a backend do?

It can call another service, send an email, process an image or return generated HTML. Returning JSON to React is one common arrangement, not the only one.

A third role

The database stores; the backend decides

A database stores and retrieves organised data. It is not the same thing as a backend. The backend coordinates the operation and uses storage where needed.

A backend can also work without a database: for example, it could convert units or return a fixed greeting. A database can live beside the app or on a separate service.

Saving something in browser localStorage is different: that saved copy belongs to that browser and origin. It is not a shared booking record for every student.

Agree on the messages

An API is the interface to the service

An API defines how software can ask another piece of software to do something. A web API exposes endpoints: defined operations reached through a method and URL path.

Example response body · JSON 
{
  "id": 42,
  "title": "Web design workshop",
  "places_left": 1
}

JSON is a text format for exchanging structured data. The frontend turns these values into a card or message; JSON is not the page design.

What if the request cannot succeed?

The response includes a status code and may explain the problem. For example, 404 can mean no matching workshop, while 403 can mean the user is not allowed to perform an operation. The frontend should handle failure as well as success.

Shared decisions

A hidden button is not permission

Hiding an admin button improves the interface, but the backend must still reject an unauthorised request. Keep private database credentials and service secrets on the server, not in JavaScript sent to users.

Backend code is not automatically secure just because it is on a server. Its checks must be implemented correctly, and its responses must only reveal appropriate data.

Choose for the task

Some sites only need static files

Usually no custom backend

A portfolio, revision notes or an in-browser calculator can run from static files. A quiz can save progress locally when cross-device sharing is not needed.

Shared server-side work

A booking system needs a shared record and centrally enforced rules. Accounts, private records and server-held API keys commonly need backend services.

A static website still needs hosting to deliver its files, but that does not mean you must write your own backend application.

FastAPI is one way to build a backend in Python. Uvicorn runs it as a web service. Next you will create a small app, test its endpoints and organise its files.

Check the distinction

Avoid these shortcuts

“Backend means database.”
The backend is application logic; a database is storage it may use.
“Frontend means everything stored on my laptop.”
A local laptop can run both sides. Frontend and backend describe roles, not permanent locations.
“React routing calls my Python endpoint.”
Changing the displayed React page and requesting backend data are separate operations. A page can do both, but one does not automatically cause the other.
“If the frontend accepts it, it must be valid.”
The backend must check inputs and permission independently.

Use the idea in a new situation

Your written responses save automatically on this device.

A library reservation

A library website lets students reserve a book. Explain one job for the frontend, one for the backend and one for the database.

Show answer guidance

The frontend shows books and collects the selected title. The backend checks whether the student may reserve it and whether a copy is available. The database stores books and reservations. The frontend displays the result returned by the backend.

A changed price

A learner changes a £20 ticket price to £1 in browser developer tools. Explain why this should not change the amount the booking system accepts.

Show answer guidance

The visible value is controlled by the browser and cannot be trusted as the real price. The backend must identify the ticket, look up its price in trusted data and calculate the total itself. Changing the interface should not change that stored price.

Ready to build

Keep the roles separate

  • Frontend: the interface and browser behaviour.
  • Backend: server-side operations and centrally enforced rules.
  • Database: shared storage when the application needs it.
  • API: the agreed messages between software components.

Key words

Quick glossary

Frontend
The interface and client-side behaviour users interact with.
Backend
Server-side application code that handles requests and rules.
Server
Software listening for requests, or the machine running it.
Database
Organised storage for data.
API
An interface for communication between software.
Endpoint
An operation reached through an HTTP method and path.
Port
A number identifying a listening network service.
