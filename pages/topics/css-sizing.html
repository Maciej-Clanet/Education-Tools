CSS Units and Sizing

A size needs a property, a number and a unit

.card { width: 300px; }

widthWhat are we sizing?

300pxHow much, and measured against what?

px means CSS pixels. A pixel width stays the same CSS length when its parent changes; it is not necessarily the same number of physical screen pixels.

Choose what to size, then choose the reference it should follow.

Does every number need a unit?

A non-zero length normally does: width: 50; is invalid, while width: 50px; is valid. Zero can be written as 0. Some properties accept unitless numbers, such as line-height: 1.5;.

The card directly contains the image element: they are parent and child. In these normal-flow examples, the parent’s content box supplies the containing block used for percentage widths. Padding and borders are left out of the calculations.

Compare a fixed width with a percentage

width: 50% requests half the containing block’s width. Inside a 600px parent, that is 600 × 0.5 = 300px. A 420px width keeps its CSS length when the parent changes.

CSS Units and Sizing

A child can be larger than its parent

.product-card { width: 300px; }
.product-image { width: 420px; }

A parent does not automatically shrink its child to make it fit.

Overflow happens when content or a child extends beyond the space available.

How could the child fit this parent?
.product-image { width: 100%; }

The child now requests the parent’s full available width: 300px here. Change the parent and this percentage width changes with it.

CSS Units and Sizing

Half of the parent—or half of the viewport?

The viewport is the webpage area inside the browser, not the entire scrollable document. 1vw is 1% of its width. A containing block can be much narrower.

Scaled model · viewport: 800 px · containing block: 400 px

50px → 50 px

50% → 200 px

50vw → 400 px

50% follows the containing block. 50vw follows the viewport.

Resize just the containing block, then just the viewport. These widths match only when their references have the same width.

CSS Units and Sizing

rem and em can follow different rulers

rem uses the root (<html>) font size. For font-size, em uses the inherited font size, usually from the parent.

Root → 2rem

2 × 16 px = 32 px

Local parent → child font-size: 2em

2 × 20 px = 40 px

Rulers are enlarged equally to show the relationship.

2rem = 32 px · child font-size: 2em = 40 px 

.local { font-size: 2em; }
.root-based { font-size: 2rem; }

Change the parent font: em responds. Change the root: rem responds.

In this model the parent has an explicit px font size, so changing the root does not change that parent reference.

About the assumed root size

At an assumed 16px root: 1rem = 16px, 2rem = 32px and 0.5rem = 8px. The controls change a teaching model, not your page settings. Do not routinely override the browser’s root font size just to simplify the maths.

Let button padding grow with its text

For padding, em uses the element’s own computed font size. Padding is the space inside the button; the two values below set vertical and horizontal space.

.button {
  font-size: 20px;
  padding: 0.5em 1em;
}
20px text

10px above/below · 20px left/right

30px text

15px above/below · 30px left/right

The same em padding scales with the button’s own text size.

Use rem when spacing should follow the shared root text scale; use em when it should follow this component’s text.

CSS Units and Sizing

max-width: let it grow, then stop

A percentage width adapts to the parent, but it can grow too wide. max-width adds an upper limit without forcing the element to reach it.

.child { width: 80%; max-width: 600px; }

Parent: 800px

Final child: 600px

800 × 0.8 = 640px requested

Capped at the maximum: 600px.

Fits inside the parent.

Try parent widths of 400px, 600px, 800px and 1200px. The calculation changes; the final width stops at 600px.

Flexible width + an upper limit lets content shrink and keeps it from becoming too wide.

Responsive design means adapting to available screen sizes. Flexible sizing is one part of it; layout and content choices matter too.

CSS Units and Sizing

min-width: give flexible width a floor

.child { width: 50%; min-width: 300px; }

Parent: 400px

Final child: 300px

400 × 0.5 = 200px requested

Raised to the minimum: 300px.

Fits inside the parent.

At a 400px parent, 50% requests 200px, so the minimum raises it to 300px. At 1000px, the child can use 500px.

Can a minimum cause overflow?

Move the parent slider to 250px. The 300px minimum still applies, so the child overflows by 50px. A lower limit protects a size; it does not guarantee a fit.

CSS Units and Sizing

Requested size must fit between the limits

.panel {
  width: 500px;
  min-width: 300px;
  max-width: 700px;
}

Minimum = lower boundary. Maximum = upper boundary.

These examples use a minimum that is no larger than the maximum.

CSS Units and Sizing

One viewport high—or at least one viewport high?

Use min-height when “at least this much height” matches the intention.

Scaled desktop example: both start with the same viewport height. The same content needs more room. Other conflicting size limits are absent.

Mobile viewport note

On mobile, browser controls can change the visible area. Standard vh uses the large viewport reference, so 100vh may extend behind visible controls. Units such as svh, lvh and dvh provide other viewport references; they are extension material, not core quiz content.

CSS Units and Sizing

max-height limits the box, not the content

.preview { max-height: 120px; }

max-height sets an upper limit. The box stops growing at this limit, but extra content can still overflow.

A height limit does not delete content. Choosing how to handle that overflow comes later.

Which sizing rule fits?

Choose the best fit for this intention, then explain the boundary or reference.

A sidebar should take 30% of its parent’s width.

A news article should use most of its parent but never exceed 800px.

An image should never be wider than its parent, and may stay smaller.

A hero should be at least as tall as the desktop viewport, with room to grow.

A panel must never become narrower than 250px.

CSS Units and Sizing

Check the common sizing traps

“50% or 100% means part or all of the browser.”

In these examples, the percentage uses the parent’s available width. That parent may be much narrower than the viewport.

“A parent automatically shrinks any child that is too wide.”

A 500px child can overflow a 300px parent. The child’s sizing rules still matter.

“If I set width, I should also set height.”

Many normal blocks should grow naturally with their content. A fixed height can leave content overflowing.

“max-width: 600px makes the width 600px.”

It sets a ceiling. An element can be narrower, for example when 90% of its parent is only 360px.

“min-width: 300px always starts at 300px.”

It sets a floor. The requested width can already be larger than that.

“min-width always helps responsiveness.”

A minimum larger than the available parent width can cause overflow.

“Responsive design just means using percentages.”

Flexible widths are one part of responsive design. Content, layout and many other choices matter too.

“rem and em use the same reference.”

rem uses the root font size. For font-size, em uses the inherited size; for padding, it uses the element’s own computed font size.

“100vh means 100 pixels.”

It means 100% of the viewport height reference. 100px is a different measurement.

Glossary

Units and sizing vocabulary

Parent / child
An element directly containing another element / the element it contains.
Containing block
The box that supplies the sizing reference. In our width examples, the parent’s available content width.
Overflow
Content or a child extending beyond the available space.
Minimum / maximum
A lower limit / an upper limit on a size.
Responsive design
Designing a website to adapt to different available screen sizes.
Viewport
The webpage area inside the browser; the reference for vw and vh.
Root
The html element. Its font size is the reference for rem.
Computed font size
The resolved text size of an element; the reference for its em padding.
