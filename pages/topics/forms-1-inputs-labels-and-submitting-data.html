Computing Model

Input goes in, processing happens, output comes out

Input and output are bigger ideas than keyboards and screens. In software, input means data or instructions provided to a system. Output means information or results produced by that system.

Input Data or instructions

What the user, another system, or a device provides.

Processing Work done by the system

Checking, calculating, searching, storing, or changing the input.

Output Information or result

What the system produces after processing.

Search engine

Input: "red panda facts". Processing: search for matches. Output: results page.

Calculator

Input: 5 + 3. Processing: addition. Output: 8.

Login form

Input: email and password. Processing: check the details. Output: success or an error.

Online shop

Input: item and quantity. Processing: calculate total. Output: order summary.

A keyboard is an input device, but the words typed into a form are also input when you are describing a software system.

Web Forms

Web forms collect input from users

Websites use forms for searching, signing in, creating accounts, entering addresses, sending messages, and choosing settings. A <form> groups the controls used to collect that information.

Submit

The user tells the form they are ready to send the values.

A real website receives, checks, stores, or uses the values.

Placeholders

Placeholder text is a hint, not a label

A placeholder can show an example value, but it disappears when typing starts. The label should remain available so users still know what the field is.

Less accessible

<input placeholder="Email address">

The only visible instruction is inside the empty box.

Better

<label for="email">Email address</label>
<input
  id="email"
  type="email"
  placeholder="name@example.com">

The label tells the user what the field is. The placeholder is only an example.

Often enough

<label for="name">Name</label>
<input id="name" type="text">

Not every input needs a placeholder. A clear label may be enough.

Input Types

The type attribute changes what kind of input is expected

<input> is one element, but type can make it behave like several useful controls. This lesson only uses a small set.

type="text"Text

General short text.

type="email"Email

Email-specific help or validation may appear.

type="password"Password

Masks display only; it does not encrypt by itself.

type="number"Number

Useful for quantities, not every value containing digits.

Switch the input type

Required fields and browser validation

<label for="email">Email address</label>
<input
  id="email"
  name="email"
  type="email"
  required>

Try submitting an empty value, an invalid email, and then a sensible email address.

Browser validation helps users, but real applications normally check important data again later.

Names and Submit

id identifies the element; name identifies the submitted value

The two attributes often look similar, but they do different jobs. Keep the question simple: id asks "which element on this page?" and name asks "what should this value be called when submitted?"

id="email"Element identifier

Used on the page, including for connecting a label.

name="email"Submitted value name

Used to label the value when form data is submitted.

same text, different jobsCommon but not magic

id and name may both be email, but they are not the same feature.

Common Mistakes

Debug forms by asking what each attribute is doing

These are realistic beginner mistakes. The fix is usually to reconnect the meaning, the element, and the submitted value.

Placeholder used as label

<input placeholder="Email">

Add a real label. Placeholder text is only a hint.

for and id do not match

<label for="email">Email</label>
<input id="username" type="email">

The label is looking for id="email", but the input has a different id.

Missing name

<input id="email" type="email">

The user can type, but the value does not have a submitted name.

Password misconception

<input type="password">

This masks characters on screen. It does not securely store or encrypt the password by itself.

Duplicate ids

<input id="email">
<input id="email">

An id should identify one element on the page.

Better pattern

<label for="email">Email</label>
<input
  id="email"
  name="email"
  type="email"
  placeholder="name@example.com"
  required>

The label, id, name, type, hint, and required rule each have a job.

Glossary

Quick glossary

Input
Data or instructions provided to a system.
Output
Information or results produced by a system.
Form
An HTML element that groups controls for collecting user input.
Input element
A void HTML element that creates a form control.
Label
Text that explains what a form control is for.
Name
The label used for a value when form data is submitted.
