09 · Architecture

What does “shared memory” mean?

The cores can use the computer’s main memory: instructions, data and results.

A familiar way to picture UMA

A smaller single-socket shared-memory computer illustrates Uniform Memory Access: software uses one main-memory access model, without choosing local versus remote NUMA RAM for each core.

Revision notes

RAM DIMMs are physical memory modules plugged into motherboard slots. “Shared” means processor resources can address/use the system’s main memory; it does not mean every application may read another application’s data. In this simplified UMA picture, ordinary applications need not place a document’s RAM in a different NUMA region beside core A rather than core B. Modern caches and processor internals are more complex; not every desktop is a textbook UMA design. The drawn memory system represents channels/controllers, not necessarily one literal bus.

10 · Architecture

Why build a larger server this way?

Non-Uniform Memory Access (NUMA) distributes memory resources as the server grows.

Smaller system · example: 256 GB RAM

Give each socket nearby memory channels

Two sockets · 256 GB + 256 GB = 512 GB RAM in this example

Grow processing, RAM capacity and local memory bandwidth together.

Revision notes

A central shared-memory resource can become harder to scale as more processors request data. Attaching memory resources to processor/socket regions spreads that demand. This motivates Non-Uniform Memory Access (NUMA): the entire computer still shares overall memory, but access paths now depend on location. Capacities illustrate a design goal, not benchmark results. DIMMs connect through memory channels/controllers associated with socket regions.

14 · Architecture

College database VM: place work near its RAM

One host: 256 GB per NUMA node. This VM needs 8 vCPUs + 32 GB RAM.

Processing: node 0 → VM memory: node 1 · REMOTE

Place the VM’s processing and memory together

Processing: node 0 → VM memory: node 0 · LOCAL

Revision notes

A virtual CPU is scheduled processing capacity, not a physical socket. Here the VM fits in one region. If its processing repeatedly accesses RAM in the other region, accesses cross the interconnect. Keeping both mostly on node 0 encourages local access. Hypervisors and operating systems try to preserve locality where possible, subject to available capacity; placement is not a promise that every access will stay local.

Which concept matters here—and why?

Render farm · 240 independent frames

Cluster reasoning: distribute independent frames over computers. Weigh input/output transfers, coordination and administration against capacity and deadlines.

Large virtualisation host · many cores and hundreds of GB of RAM

NUMA reasoning: sockets bring processing and local memory resources. VM processing and memory placement affect how often requests cross the interconnect.

Smaller single-socket shared-memory computer

UMA reasoning: the simplified uniform model avoids local/remote NUMA placement decisions. Adequate memory bandwidth still matters.

Name the architectural level, then link it to the workload.

Revision notes

These are suitability arguments rather than three exclusive product choices. A cluster can use larger NUMA servers or smaller shared-memory computers. Explain what the work needs, the benefits, communication or locality costs, and a justified conclusion.

20 · Architecture

Check the six common traps

“A cluster is one machine with many CPUs.”

Cluster nodes are separate computers.

“A NUMA node is another computer.”

A NUMA node is a processor/memory locality region inside one shared-memory computer.

“NUMA RAM is private.”

Remote RAM remains accessible within the shared-memory system.

“UMA means no contention.”

Uniform access does not mean unlimited memory bandwidth.

“NUMA is automatically faster.”

NUMA supports scaling, but access patterns and locality affect performance.

“Cluster, UMA and NUMA are mutually exclusive.”

A cluster can contain NUMA servers. The labels describe different levels.

22 · Architecture

Apply the ideas in longer answers

Drafts save automatically in this browser. Explain causes and consequences; use the guides after writing.

4 marks

Question 1

Explain what is meant by cluster computing.

Show answer guide

Separate computer nodes each have their own processors and RAM. They communicate over a network; software coordinates their work to provide capacity or services. Explain the cooperation rather than just listing parts.

4 marks

Question 2

Explain the difference between UMA and NUMA.

Show answer guide

Both are shared-memory multiprocessor models. UMA provides a uniform access relationship. NUMA has physically distributed memory: local access generally has lower latency than remote access. Explain one placement or scaling implication.

6 marks

Question 3

Explain why adding processors to a UMA system can cause performance problems.

Show answer guide

More processors can issue more simultaneous memory requests. Shared bandwidth is finite; requests compete and may wait. Processors can spend time waiting rather than doing useful work. Uniform access does not remove contention. Explain why extra processors may produce smaller gains than expected, without claiming a fixed processor limit.

6 marks

Question 4

Explain why memory locality matters in a NUMA system.

Show answer guide

Identify task and data placement. Local accesses use nearby memory; remote accesses cross an interconnect and generally have higher latency. Repeated remote traffic can increase waiting and pressure on shared links. Keeping frequently used data near processing can help, although it does not eliminate all remote access or contention.

8 marks

Question 5

Analyse why a rendering company might use a cluster rather than one very large computer.

Show answer guide

Independent frames divide across nodes, allowing concurrent rendering and growth by adding machines. Balance this against transferring inputs/results, uneven task sizes, coordination, software and administration costs. A larger single machine avoids some network coordination but may offer less convenient expansion. Reach a workload-specific conclusion; do not promise linear speedup or automatic failover.

8 marks

Question 6

Analyse why NUMA may suit a large virtualisation host, and explain the placement trade-offs.

Show answer guide

Each socket region can add processing, RAM capacity and local memory bandwidth for many VMs. A VM with processing and frequently used memory in the same region can make mostly local accesses. Remote placement crosses the interconnect and generally increases latency. Discuss capacity constraints, remote traffic and placement complexity; conclude using the host’s workload rather than claiming NUMA is always faster.

12 marks

Question 7

An organisation needs large workloads processed across many processors and machines. Evaluate the architectural factors it should consider.

Show answer guide

Distinguish scaling between computers from shared-memory organisation inside each one. Evaluate divisibility, shared-data needs, processor/RAM scale, communication latency, memory bandwidth and locality. Consider resilient-service design, coordination, cost and administration. Compare a cluster for independent work with a large shared-memory server for tightly cooperating work. A cluster of NUMA servers can combine approaches. Give a justified conclusion tied to requirements and acknowledge trade-offs.

Glossary

Quick glossary

Cluster computing
An approach where several separate computers or nodes work together on a task or service.
UMA
Uniform memory access, where processors share memory with the same conceptual access relationship.
NUMA
Non-uniform memory access, where some memory is faster to reach than other memory.
Node
A cluster node is a separate computer. A NUMA node is a processor/memory region within one shared-memory system.
Memory locality
The idea that data is faster to access when it is physically closer to the processor using it.
Latency
Delay before a memory access is served; remote NUMA access generally has higher latency than local access.
Bandwidth
Amount of data a path or memory system can transfer per unit of time.
Contention
Competition when multiple requests need the same limited resource.
Shared memory
Overall memory that processors within one system can access; it need not all be physically next to every processor.
CPU core
A processing unit within a CPU package; a package can contain many cores.
CPU socket
The motherboard connection that holds a CPU package.
DIMM
A physical RAM module fitted into a motherboard memory slot.
NUMA node
A processor/memory locality region within one shared-memory computer. Not necessarily one whole physical socket.

Remember

Separate machines is not the same as shared memory

  • Clusters are about several nodes working together.
  • UMA and NUMA are about memory access inside a system.
  • NUMA differs from UMA because locality changes speed.
  • In longer answers, link the model to the workload, not just the definition.
