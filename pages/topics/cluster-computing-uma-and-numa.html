Uniform latency ≠ unlimited bandwidth

CPU 1 ↓ CPU 2 ↓ CPU 3 ↓ CPU 4 ↓
Requests waiting for service
Shared memory bandwidth

An equivalent access relationship can still involve waiting.

Revision notes

Latency is the delay for an access; bandwidth is the amount of data transferred per unit of time. When combined demand exceeds what the memory system can serve, requests compete. Adding processors may therefore deliver diminishing performance gains; UMA is not limited to a fixed small processor count.

40 · Architecture

Exam-style practice

Drafts save automatically in this browser. Explain causes and consequences; use the guides after writing.

4 marks

Question 1

Explain what is meant by cluster computing.

Show answer guide

Separate computer nodes each have their own processors and RAM. They communicate over a network; software coordinates their work to provide capacity or services. Explain the cooperation rather than just listing parts.

4 marks

Question 2

Explain the difference between UMA and NUMA.

Show answer guide

Both are shared-memory multiprocessor models. UMA provides a uniform access relationship. NUMA has physically distributed memory: local access generally has lower latency than remote access. Explain one placement or scaling implication.

6 marks

Question 3

Explain why adding processors to a UMA system can cause performance problems.

Show answer guide

More processors can issue more simultaneous memory requests. Shared bandwidth is finite; requests compete and may wait. Processors can spend time waiting rather than doing useful work. Uniform access does not remove contention. Explain why extra processors may produce smaller gains than expected, without claiming a fixed processor limit.

6 marks

Question 4

Explain why memory locality matters in a NUMA system.

Show answer guide

Identify task and data placement. Local accesses use nearby memory; remote accesses cross an interconnect and generally have higher latency. Repeated remote traffic can increase waiting and pressure on shared links. Keeping frequently used data near processing can help, although it does not eliminate all remote access or contention.

8 marks

Question 5

Analyse why a rendering company might use a cluster rather than one very large computer.

Show answer guide

Independent frames divide across nodes, allowing concurrent rendering and growth by adding machines. Balance this against transferring inputs/results, uneven task sizes, coordination, software and administration costs. A larger single machine avoids some network coordination but may offer less convenient expansion. Reach a workload-specific conclusion; do not promise linear speedup or automatic failover.

8 marks

Question 6

Analyse the advantages and disadvantages of NUMA for a large multiprocessor server.

Show answer guide

Each region contributes processor capacity, RAM and local bandwidth. This can help scale a shared-memory workload. Balance those gains against remote-access latency, traffic and placement complexity. Explain why OS/application locality awareness and the workload’s access pattern affect suitability; NUMA is not always faster.

12 marks

Question 7

An organisation needs large workloads processed across many processors and machines. Evaluate the architectural factors it should consider.

Show answer guide

Distinguish scaling between computers from shared-memory organisation inside each one. Evaluate divisibility, shared-data needs, processor/RAM scale, communication latency, memory bandwidth and locality. Consider resilient-service design, coordination, cost and administration. Compare a cluster for independent work with a large shared-memory server for tightly cooperating work. A cluster of NUMA servers can combine approaches. Give a justified conclusion tied to requirements and acknowledge trade-offs.

Glossary

Quick glossary

Cluster computing
An approach where several separate computers or nodes work together on a task or service.
UMA
Uniform memory access, where processors share memory with the same conceptual access relationship.
NUMA
Non-uniform memory access, where some memory is faster to reach than other memory.
Node
A cluster node is a separate computer. A NUMA node is a processor/memory region within one shared-memory system.
Memory locality
The idea that data is faster to access when it is physically closer to the processor using it.
Latency
Delay before a memory access is served; remote NUMA access generally has higher latency than local access.
Bandwidth
Amount of data a path or memory system can transfer per unit of time.
Contention
Competition when multiple requests need the same limited resource.
Shared memory
Overall memory that processors within one system can access; it need not all be physically next to every processor.

Remember

Separate machines is not the same as shared memory

  • Clusters are about several nodes working together.
  • UMA and NUMA are about memory access inside a system.
  • NUMA differs from UMA because locality changes speed.
  • In longer answers, link the model to the workload, not just the definition.
