04 · Text representation

Codes store characters; fonts draw them

Same letter, different fonts

AAA

A font is a design for drawing letters and other symbols. Changing the font changes the appearance, not which character is stored.

Digits can be text too

Room 7

Here, 7 is part of a label. It needs a character code just like the letters and the space. We are displaying a room name, not doing a calculation.

Text digits and numeric values

Software can interpret a sequence of text digits as a number when it needs to calculate. The character code used to write a digit is a different thing from the numeric value it represents. For example, ASCII gives the text digit 0 the code value 48.

05 · Text representation

Seven bits give 128 codes

ASCII is an agreed character-coding standard. Standard ASCII uses seven-bit values.

1 bit20 or 1
→
2 bits400, 01, 10, 11
→
7 bits1282⁷ possible codes

128 positions, numbered 0 to 127. Counting starts at zero.

Is the largest standard ASCII code 128?

No. The largest value is 127. There are 128 values when zero is included.

Some codes do not draw a symbol

ASCII includes control codes as well as printable characters. Line feed (LF) tells this text display to start a new line.

LF has value 10: 0001010 in seven bits. It still occupies a position in the data.

How many codes are in H, i, LF, A?

Four. A control code counts even though it is not a visible letter.

Other controls and line endings

Tab has value 9 and carriage return has value 13. Some systems use LF alone for a line break; others use CR followed by LF. Our example explicitly uses one LF code.

08 · Text representation

ASCII needs seven bits; storage uses a byte

Computers commonly organise memory and files in eight-bit bytes. Giving each ASCII code its own byte lets software find the next code at the next byte position.

ASCII code for A · 7 bits1000001Value 65
→
Stored in one byte · 8 bits01000001Still value 65

The extra leading zero does not change the value. Seven bits describe the ASCII code; eight bits are used to store it here.

Why give each code its own byte?

With one character code in each byte, software can read or locate the next code at the next byte position. This is a common storage convention, rather than a requirement to pack seven-bit values tightly across byte boundaries. ASCII itself still has only 128 code values.

A name does not fit

A club register must preserve members’ names. Standard ASCII can represent every letter in Jose, but not every character in José.

Inside standard ASCII

£ and Ω are also outside standard ASCII. A broader repertoire is needed to preserve them.

Would changing José to Jose preserve the original text?

No. It changes the name. The storage system should support the characters people actually use.

10 · Text representation

Unicode assigns code points

Unicode gives characters from many writing systems, symbols and emoji standard identifiers called code points.

AU+0041Latin letter
éU+00E9Accented Latin letter
漢U+6F22CJK ideograph
😀U+1F600Emoji

U+ introduces a code point written in hexadecimal. It is an identifier, not a picture of the character.

Hexadecimal reminder

Hexadecimal uses digits 0–9 and A–F. U+0041 is denary 65. The number assigned to A agrees with its ASCII value.

11 · Text representation

An encoding turns code points into bytes

Unicode identifies the character. UTF-8 gives the rules for storing that identifier as bytes.

CharacteréWhat the reader sees
→
Unicode code pointU+00E9The character’s identifier
→
UTF-8 stored bytesC3A9Two bytes for this character

Decoding reverses this process: UTF-8 reads the two bytes together and identifies é.

C3 and A9 are byte values written in hexadecimal. The computer stores their bits. You do not need to memorise or calculate the UTF-8 byte patterns.

See the stored bits

C3 = 11000011 and A9 = 10101001. UTF-8 specifies this two-byte sequence for U+00E9.

UTF-8 uses variable-length codes

UTF-8 stores these code points using one to four bytes. Each box below is one byte.

Does every Unicode character use the same amount of storage?

No. UTF-8 uses different numbers of bytes for these code points. A larger character repertoire does not mean every character has one fixed, larger size.

Unicode, UTF-16 and UTF-32

Unicode is not a fixed 16-bit storage scheme. UTF-8, UTF-16 and UTF-32 are different encoding forms. UTF-8 uses one to four bytes for a Unicode scalar value. UTF-16 uses one or two 16-bit units for a Unicode scalar value; UTF-32 uses one 32-bit unit. A scalar value is a Unicode code point excluding the reserved surrogate range.

How software chooses the encoding

A file format or application can define a default. A file or message can declare its encoding, or a user can select it when opening the file. For example, a web server can label text as UTF-8 so the browser uses the matching decoder. Guessing from the bytes is unreliable.

Why is “Unicode has more characters” an incomplete justification?

Broader coverage preserves the actual names and symbols. Sender, storage and receiver must also agree on the encoding, or those supported characters can still be misread.

Missing glyphs and “extended ASCII”

A font without the needed glyph may display an empty box even when the text is correctly encoded. That is a display problem. Also, “extended ASCII” describes various eight-bit mappings, not one universal standard; systems using different mappings can disagree.

Why the counter says code points

One visible character can use more than one code point. Precomposed é is U+00E9; e followed by the combining acute accent U+0301 can look the same. Some emoji also use sequences of code points. This inspector counts code points, not perceived characters.

17 · Text representation

Repair three common mistakes

“Changing the font changes the character encoding.”

A font changes how a character is drawn. The same stored A can appear in several fonts without changing its code.

“Unicode stores every character in exactly 16 bits.”

Unicode code points and encoded storage are different things. Our UTF-8 examples have different lengths: A uses one byte, while 😀 uses four.

“Unicode support alone prevents garbled text.”

Supporting the characters is only part of the solution. The receiver must also use the encoding that matches the sender. Reading UTF-8 data with the wrong decoder can still produce the wrong text.

Show answer guidance

A coded character set assigns a number to each character. An encoding represents them as binary data for storage or transmission.

The receiver interprets the data using the agreed encoding to recover S, T, O and P. If it uses a different interpretation, the same data can produce the wrong text. The agreement lets the intended message survive the transfer.

Practice 2 · Preserve people’s names

An ASCII-only membership system stores Jose instead of José and cannot store 李. Explain the problem and justify a suitable approach for storing and sending these names.

Show answer guidance

Standard ASCII has only 128 positions and does not include é or 李. Removing or replacing these characters changes members’ actual names.

Use software/storage that supports Unicode, with an agreed encoding such as UTF-8 for saving and exchanging the data. The receiver must decode that encoding correctly. This provides character coverage and preserves the intended text across systems.

Glossary

Quick glossary

Character set
The available characters; a coded character set assigns a number to each.
ASCII
A character-coding standard with 128 positions numbered 0–127, expressed in seven bits.
Unicode
A standard assigning code points to characters from many writing systems, symbols and emoji.
Code point
A numbered position, written as U+ followed by hexadecimal in Unicode.
UTF-8
A common Unicode encoding used to store code points as bytes.

Remember

Codes need interpretation

  • Character sets let systems interpret text consistently.
  • ASCII is compact but limited to 128 standard codes.
  • Unicode coverage and consistent encoding preserve international text.
  • Encoding mismatches can create garbled text.
